# Drag-and-Drop Tiles (#5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players can drag tiles with a mouse or a finger:
- rack → empty square (place)
- placed tile → another empty square (move)
- placed tile → rack (take back)
- within the rack (rearrange)

A drop in the wrong place slides the tile back. Tap-to-place keeps working.

**Architecture:**
- A new UMD module `js/drag.js` (global `Drag`) has two parts:
  - **Pure decision function:** `Drag.decide`, unit-tested. It answers "what does this drop mean?".
  - **Browser-only pointer controller:** `Drag.attach`, which handles pointer events, the floating tile, square highlighting, rack "make room", animations and click suppression.
- `Rack.move` (pure) reorders the local rack order.
- `view-room.js` supplies hooks that read and change the existing `ui.temp`, `ui.selected` and `ui.rackOrder`. It already re-renders through `update()`.
- Nothing is written to Firebase until Play word, exactly as today.

**Tech Stack:** Vanilla JS Pointer Events (mouse + touch + pen in one API), CSS, `node:test`. No libraries.

**Spec:** the design agreed in chat on 2026-11-02 (feature request #5). The user accepted all recommendations:
- **Grab:** after about 6px of movement the tile lifts and follows the pointer, floating slightly above a finger.
- **Highlight:** the square under the pointer lights up. Green means it can be dropped there; red means occupied or not allowed.
- **Drop on an empty square on my turn:** the tile settles there with a small bounce and the "place" sound.
- **Drop anywhere invalid** (an occupied square, off the board, not my turn): the tile slides back to its rack slot.
- **Moving tiles placed this turn:** they can be dragged to another empty square, or onto the rack to take them back.
- **Rearranging the rack:** drag within the rack at any time, including the opponent's turn. Other tiles make room. Local only, like 🔀 Shuffle.
- **Tap:** a quick tap with no drag still selects, and tap-then-tap still places.
- **Who can drag:** spectators and the host can't.
- **Interrupted drags:** if the opponent's move takes the target square, or the turn ends mid-drag, the tile returns to the rack.
- **Reduced motion:** no slide or bounce; tiles snap.
- **Scrolling:** the page doesn't scroll while dragging on phones.
- **Layouts:** works in both the phone layout and the desktop landscape layout.

## Global Constraints

- No Firebase writes from dragging; `Store.mutateRoom` is only reached through the existing Play / Pass / appeal buttons.
- Placement rules are unchanged: board squares that already hold a letter are never droppable, and placement only happens when it's my turn and not `ui.busy`, `ui.rejected` or a pending appeal (`myTurn()` covers paused and pending).
- User strings never go through `innerHTML` in new code. Letters come from the rack (`A`–`Z`); render the floating tile with `textContent`.
- AA contrast in both themes for the drop highlights: a green outline means OK, red means not allowed, both on the square. Highlights are outlines, so the square's own text contrast is untouched.
- 360×640 phone fit unchanged. `touch-action: none` only on draggable tiles (`#rack .tile`, board `.tile.temp`), so the page can still scroll elsewhere.
- `prefers-reduced-motion: reduce`: no slide-back, bounce or make-room animation.
- Commits get no `Co-Authored-By` trailer.

## Review Focus

1. **A re-render in the middle of a drag** (opponent move, clock tick, presence) replaces the rack and board elements. The drag survives, because its state lives in `ui.drag` and indices, not in DOM nodes. A target square taken by the new move makes the drop `return`. Test: `Drag.decide` with `occupied` true (Task 1) plus E2E check 8 (Task 3).
2. **A quick tap or a tiny wobble (< 6px)** must still act as a click, and a real drag must not also fire the click (no "select + place twice"). E2E checks 6 and 7 (Task 3).
3. **Dragging the second of two identical letters** (E, E): rack indices, not letters, decide which slot empties. Test: `Rack.move` with repeats plus E2E check 1 using `data-i` (Task 3).
4. **The turn ends or the game pauses mid-drag:** the tile returns, and no placement survives into the opponent's turn. Test: `decide` with `myTurn: false` (Task 1).
5. **Phone touch drag:** the page doesn't scroll, and the floating tile isn't hidden under the finger. E2E check 7 asserts `scrollY === 0` and that the ghost's centre is above the touch point (Task 3).

### Task 1: Pure logic — `Rack.move` and `Drag.decide`

**Files:**
- Modify: `js/rack.js`, `tests/rack.test.js`
- Create: `js/drag.js`, `tests/drag.test.js`
- Modify: `index.html` (script tag after `js/layout.js`)

**Interfaces:**
- Produces:
  - `Rack.move(order: number[], from: number, to: number) -> number[]`.
    - `from` is a display position.
    - `to` is an insertion position in `0..order.length`, measured before the tile is removed.
    - It returns a new array and doesn't mutate its input.
  - `Drag.THRESHOLD_PX = 6`
  - `Drag.decide({ from, to, myTurn, locked, occupied }) -> action`.
    - Inputs:
      - `from`: `{ kind: 'rack', index }` (a rack index) or `{ kind: 'board', r, c }` (a tile placed this turn).
      - `to`: `{ kind: 'square', r, c }`, `{ kind: 'rack', pos }` (pos = insertion position) or `{ kind: 'none' }`.
      - `myTurn`: the result of view-room's `myTurn()`.
      - `locked`: `ui.busy || !!ui.rejected`.
      - `occupied(r, c) -> boolean`: true when the board has a letter there or another placed tile sits there.
    - Actions:
      - `{ type: 'place', index, r, c }`: rack → empty square, when `myTurn && !locked`.
      - `{ type: 'move', from: { r, c }, r, c }`: board → a different empty square, when `myTurn && !locked`.
      - `{ type: 'unplace', r, c }`: board → rack.
      - `{ type: 'reorder', index, pos }`: rack → rack, allowed any time.
      - `{ type: 'return' }`: everything else, including board → its own square.

### Task 2: Pointer controller and room wiring

**Files:**
- Modify: `js/drag.js` (`Drag.attach`), `js/view-room.js` (`buildLive`, `detachLive`, `update`, a new `applyDrag`), `css/style.css`

**Interfaces:**
- Consumes: `Drag.decide`, `Drag.THRESHOLD_PX`, `Rack.move`.
- Produces: `Drag.attach(rootEl, hooks) -> detach()`, with these hooks:
  - `source(targetEl) -> from | null`. view-room returns `{kind:'rack', index}` for a `#rack .tile:not(.used)` when seated. It returns `{kind:'board', r, c}` for a `.sq .tile.temp` when `myTurn()` and not locked. Otherwise `null`.
  - `context() -> { myTurn, locked, occupied }`
  - `start(from)`: view-room sets `ui.drag = from` and calls `update()`. While `ui.drag` is set, `update()` passes the rack index as used (an empty slot), or leaves the dragged temp tile out of `temp`.
  - `finish(action)`: view-room clears `ui.drag` and applies the action:
    - **place:** push `{r, c, letter: rack[index], rackIndex: index}`, clear `ui.selected`, `Sound.play('place')`
    - **move:** update that temp entry's `r`/`c`
    - **unplace:** remove it
    - **reorder:** `ui.rackOrder = { key, order: Rack.move(order, displayPosOf(index), pos) }`
    - **return:** nothing

    Then it calls `update()`. For place and move it adds the class `drop-in` to the tile now at `r`/`c`, unless reduced motion is on.
  - `returnRect(from) -> DOMRect | null`: the rack slot of `from.index`, or of the temp tile's `rackIndex`. The ghost animates there on `return` and `unplace`.
- Controller behaviour (`Drag.attach`):
  - **Start:** a `pointerdown` on `rootEl` (primary button, or touch/pen) whose `hooks.source` is not null records the start point.
  - **Lift:** once the pointer has moved `THRESHOLD_PX`, it calls `hooks.start` and creates `.drag-ghost`, a `position: fixed` copy of the tile at the source tile's size. For touch, the ghost sits 0.8 × its height above the finger. `pointer-events: none`.
  - **Moving:** `pointermove`/`pointerup`/`pointercancel` are listened for on `window`.
  - **Hit-testing:** `document.elementFromPoint`, finding `.sq[data-r]` or `#rack`.
  - **Highlights:** while over a square it adds `.drop-ok` or `.drop-bad`, using `Drag.decide` with the current context. While over the rack it computes `pos` from tile centres and shifts the tiles at or after `pos` by one tile width (`.make-room`, a transform transition; none with reduced motion).
  - **Drop:** on `pointerup` it decides, calls `hooks.finish(action)`, and animates the ghost: to the square for place/move, or back to `returnRect` for return/unplace. It then removes the ghost. Reduced motion removes it at once.
  - **Cancel:** `pointercancel` or `Escape` → `return`.
  - **Click suppression:** after a real drag it swallows the next `click` in the capture phase, so tap handlers don't fire.
  - **Multi-touch:** only one pointer is tracked; any second pointer is ignored.
