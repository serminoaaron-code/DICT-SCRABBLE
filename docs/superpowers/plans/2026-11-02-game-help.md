# "How to play" Page + Polish Leftovers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Add the `#gamehelp` "How to play" page (Player / Host / Watch guides, mobile-first, both themes, accessible). A seated player in a live game gets it in a new tab.
- Clear the seven polish leftovers (L1–L7).

**Architecture:**
- **New module `js/view-help.js`** (UMD):
  - pure: `Help.roleOf(hash)` and `Help.facts()`, with unit tests; the facts come from the game's constants;
  - browser only: `HelpView.show(el, role)`, which renders static markup.
- **Styles:** new `css/help.css`.
- **Wiring:** `app.js` routes `#gamehelp` and handles the header link. `view-room.js` sets `App.inLiveSeat`, so the link opens a new tab during your own live game.

**Tech Stack:** vanilla JS (UMD, no build step), CSS tokens, `node --test`, the CDP E2E harness (`.superpowers/e2e/`).

**Spec:** `docs/superpowers/specs/2026-11-02-game-help-design.md`

## Global Constraints

- **Routes:**
  - `#gamehelp`, `#gamehelp=player|host|watch`; an unknown role opens player;
  - the header link reads **"How to play"**, or **"Help"** under 480px;
  - the big screen never shows it.
- **Data:** the page reads no game data and never shows the host password.
- **Numbers come from the code:**
  - `Match.TURN_MS` (60 s);
  - `ScrabbleEngine.TIER_MIN = [0, 8, 15, 25, 40]` (new; `celebrationTier` uses it), with any bingo being IMPOSSIBLE!!!;
  - `ScrabbleEngine.BINGO_BONUS` (50);
  - `Match.TAUNT_COOLDOWN_MS` (10 s);
  - `Match.SUDDEN_DEATH_MAX_ROUNDS` (3);
  - the match-length chip reads "5 / 10 / 15-minute matches (or a custom length)".
- **Mobile at 360px:**
  - one column, no horizontal scroll;
  - the role picker is a compact row of three (Player / Host / Watch);
  - text at least 14px; tap targets at least 44px tall.
- **Accessibility:**
  - one `h1`, an `h2` per role, steps as an ordered list with an `h3` each;
  - the role picker is a real tablist (arrow keys move focus; Enter or Space picks);
  - the mini pictures are `aria-hidden`;
  - reduced motion means no animation;
  - WCAG AA in both themes.
- **A seated player in a live game** (`live` / `suddenDeath` / `hostDecision`): the header help link opens in a new tab (`noopener`). Otherwise it opens in the same tab.
- **Leftovers:** behaviour exactly as in the spec table L1–L7.

## Review Focus

1. **At 360px with the larger phone text setting** (`font-size` 112.5% on `html`), the help page, header and role row still don't scroll sideways. Task 3's E2E checks it.
2. **A help link opened while the player's game is between states** (`waiting` → `live`, or `live` → `final`) follows the current state: a new tab only while live. Task 4's E2E checks both edges.
3. **The keyboard focus ring (L1)** shows on the help tablist, the rack tiles and the board squares that are buttons, but not after a mouse click or tap. Task 5's E2E checks it.
4. **Opening `#gamehelp=host` directly, then Back:** Back returns to the previous route, and picking a role never adds history entries. Task 3's E2E checks it.
5. **Theme switch while on the help page:** every element re-colours with no hard-coded colour left behind. Task 3's contrast sweep in both themes checks it.
